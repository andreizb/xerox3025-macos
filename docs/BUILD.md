# Build a private, reviewable package

Requires an Apple Silicon Mac, Xcode/Command Line Tools, native Python 3.12+,
CMake, pkg-config, GNU libtool, gettext/autopoint, Git, make and ordinary Unix
build tools. The build recognizes the usual Apple Silicon Homebrew locations
for GNU libtool and gettext. These are build prerequisites; the script does not
install system packages. The tested compiler ABI target is macOS 14; actual
compatibility remains limited to the tested OS in STATUS.md.

This is a network-only scanner build; no USB acquisition path is enabled.

From the checkout root:

```sh
python3 scripts/build.py
cp packaging/device.example.json packaging/device.json
```

Edit the ignored `device.json` with the printer's actual hardware UUID, desired
published name and serial number (the serial may be empty). Obtain the UUID
from the printer's Bonjour/IPP identity; a CUPS queue UUID is a different value.
For an existing direct Bonjour AirPrint queue, `lpstat -v` may show a
`dnssd://.../?uuid=...` URI: use that URI's hardware UUID, not the separate CUPS
queue UUID. If the queue already points at a local proxy, use its original
private review or inspect the printer's Bonjour advertisement instead.
The runtime resolves that identity to the current host using Bonjour, so do
not put an IP address in this configuration. `src/discover.c` implements the
native discovery helper. The example identifiers must be replaced.

```sh
python3 scripts/package.py --identity-config packaging/device.json
python3 packaging/accept-staging.py dist/Xerox3025Bridge-candidate --evidence evidence/staging
```

Packaging checks every Mach-O runtime for ARM64, relocates private dependencies,
verifies local ad-hoc signatures and emits manifests plus corresponding source.
The staging check uses a temporary Library and fake association; it does not
start the scanner or change the real queue. Inspect the generated installer,
manifests and docs before any installation. A configured installer is private.

For acquisition without queue association, the package's `install` starts the
per-user service. Associating the original printer entry needs a separate review
using a PPD generated by native Add Printer after bridge discovery. See
[QUEUE_ASSOCIATION.md](QUEUE_ASSOCIATION.md) for the two-stage procedure and its
existing-installation guard. A separately listed scanner alone is intermediate.

Deliver runtime updates by rebuilding, reviewing the new package, uninstalling
and reinstalling; do not overwrite files inside an active installation. After a
new installation, check System Settings > Privacy & Security > Local Network if
macOS requests access or the service discovers the printer but cannot acquire.
A runtime replacement was associated with a local-network permission failure on
the tested Mac; this is an observed troubleshooting case, not a general claim
about how macOS identifies every process. A successful device inquiry alone does
not prove a working scan or establish the cause of an acquisition failure.

Removal is available through `./uninstall-all` in the generated scanner package,
or `bash packaging/uninstall-all` in this source checkout. Each component also
keeps its individual uninstaller in its own Application Support directory.
Remove the toner component before the scanner so the direct printer URI is
restored first. Deleting this checkout does not uninstall running components.

The build pins source revisions and SHA-256 archives in `sources.lock.json`.
`build/`, `prefix/`, `build-tools/`, `upstream/` and `downloads/` are disposable
local outputs. Extract a generated `corresponding-source.tar.gz` and run
`python3 scripts/build.py --offline` inside its `printer-modernization/` root
to rebuild without downloading upstream sources. Build prerequisites still need
to exist. This is a pinned-source recipe, not a bit-for-bit reproducibility claim.

Optional toner package, from the repository root:

```sh
python3 experiments/ipp-supply-proxy/build.py
python3 experiments/ipp-supply-proxy/package.py --output dist/Xerox3025SupplyProxy-candidate
```

This downloads a pinned native Go toolchain into the experiment's own build
folder and runs its tests. Follow that component's INSTALLATION.md only after
reviewing the additional dependency it introduces for printing. Optional native
documents and deskew have their own build/package instructions.
