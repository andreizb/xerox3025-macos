# Associate scanning with the preserved Xerox queue

The accepted route uses Apple's existing signed ARM-native AirScanScanner module.
Native Add Printer generated these three fields for the real discovered bridge:
`APScannerUUID`, `APICADriver`, and `APScannerModulePath`. The helper transfers
only those fields to the original AirPrint PPD after validating matching hardware
identity. It does not supply a new ICA module or recreate the original queue.
This was accepted on the tested Mac; macOS association behavior must be rechecked
on each supported release.

A fresh machine requires a discovery stage before the final associated install:

1. Preserve the original queue and its settings. Configure and build the scanner
   package for the actual hardware identity. Review and run its `./install` to
   expose the bridge without yet modifying the original queue.
2. Validate actual acquisition, then use Apple's Add Printer interface to add a
   clearly named temporary AirPrint queue for the same discovered multifunction
   device. Save that temporary queue's macOS-generated PPD from `/etc/cups/ppd/`
   in a private folder. A generated PPD must contain the three scanner fields and
   point at `/System/Library/Image Capture/Devices/AirScanScanner.app`.
3. Uninstall the initial unassociated bridge with its `./uninstall` before the
   final installation; the installer deliberately refuses to overwrite a service.
   Keep the generated PPD for the association review.
4. Prepare a review from the source checkout (or the packaged copy in
   `maintenance/associate-queue.py`):

```sh
python3 scripts/associate-queue.py --queue EXISTING_QUEUE_ID   --generated-ppd /absolute/private/native-generated.ppd   --output /absolute/private/new-queue-review
```

The review output must be new and its parent must exist. Inspect `changes.patch`
and `manifest.json`: only the three scanner fields should change. Both PPDs and
the original Bonjour URI must agree on hardware identity. An `ipp2ppd` comment
is a consistency check, not proof that an arbitrary PPD was generated by Apple.
Do not use the experimental toner-hook option; it did not fix the observed bar.

From the reviewed scanner package directory, install with that review:

```sh
./install --association-review /absolute/private/new-queue-review
```

CUPS uses its local socket for administration. If macOS requires authorization,
the review remains available. Do not change CUPS authorization policy. The tools
refuse changed reviews, wrong identities and competing print changes. Association
maintenance needs native Python; the scanner runtime itself does not.

Test the original entry's Open Scanner/Print Center button, independent Image
Capture and Preview separately. Remove only the temporary queue after the original
entry is accepted. Retain private rollback records in the installed Library.
If association fields or actual entry behavior differ, stop and investigate the
specific macOS behavior; do not claim a separate scanner satisfies association.

If adding toner correction, do it after scanner association. Remove toner first:
its uninstaller restores the direct Bonjour URI before scanner rollback. The
scanner uninstaller restores its reviewed PPD while keeping the queue. Conflicts
retain evidence instead of deleting the only recovery copy. Both runtimes live
under the current user's Library/Application Support and start through LaunchAgents.
